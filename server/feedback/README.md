# Отзывы тестеров Vita

Кнопка в настройках игры отправляет отзыв без регистрации в комментарии
[темы тестеров #5](https://github.com/crownfall90-dot/mobile-game/issues/5).
Текст публичный. Версия, экран и уровень добавляются автоматически;
модель телефона и версия системы — только по выбору игрока.

## Размещение

Из этой папки, после входа в Cloudflare через Wrangler:

```powershell
npx wrangler deploy
npx wrangler secret put GITHUB_TOKEN
npx wrangler secret put RATE_SALT
```

`GITHUB_TOKEN`: отдельный fine-grained token GitHub, только для
`crownfall90-dot/mobile-game`, Issues: Read and write. Вводить в запрос
Wrangler, не сохранять в репозитории или APK. `RATE_SALT`: случайная
секретная строка. При смене/истечении токена обновить секрет.
Для новых аккаунтов может потребоваться включение Workers/subdomain.

После размещения проверить `GET https://<worker>/health`: 200 и ready=true.
В `data/telemetry.json` установить `feedback_url` в
`https://<worker>/feedback`. Затем проверить реальную отправку и повтор
того же ID (один комментарий) и собрать новый APK. Пустой адрес честно
отключает отправку, оставляя черновик. Старые APK адрес не получат сами.

## Проверки

```powershell
node server/feedback/check.mjs
npx wrangler deploy --dry-run
```

Проверка клиента включена в существующий запуск Godot `-- --smoke`.
Она не обращается к серверу и не пишет профиль.

## Ограничения

- Только текст, 10–1500 знаков; тело запроса до 16 KiB. Скриншотов нет.
- 10 запросов в минуту на IP через Cloudflare; до 200 новых отзывов в сутки
  на весь приёмник. IP не публикуется; ключ ограничения хешируется с солью.
- Один Durable Object последовательно обрабатывает отзывы небольшой группы.
  Идентификаторы принятых/ожидающих отзывов сохраняются без срока удаления.
- При потере ответа GitHub повтор ищет маркер принятого сообщения, не создавая
  второй комментарий. Если комментарий так и не найден (до 300 комментариев
  после времени первой попытки), запись остаётся pending. Владелец должен
  проверить тему и решить судьбу записи; автоматической повторной публикации
  в неоднозначном случае нет. Изменение текста создаёт новый ID.
- /health проверяет наличие настроек, а действительность токена подтверждается
  только успешной отправкой.
