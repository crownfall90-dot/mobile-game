# Публикация в Google Play: тексты, чек-лист, сборка AAB

Этот файл для владельца проекта. Здесь всё, что нужно сделать своими руками, чтобы игра
«Зелья и засовы» / "Pins & Potions" вышла в Google Play: тексты страницы, ответы на анкеты,
порядок шагов и сборка AAB на Windows. Основано на DESIGN §15 (статус на сентябрь 2026).

> Если игра будет переименована, поменяй название в трёх местах: строка `app.title`
> (`data/strings/core.json`), тексты ниже и страница `docs/privacy/index.html`.

## 1. Тексты страницы в Google Play

Лимиты Google Play: название до 30 символов (вместе с подзаголовком), краткое описание
до 80, полное описание до 4000. Длины ниже посчитаны скриптом.

| Поле | RU | EN |
|---|---|---|
| Название (≤ 30) | `Зелья и засовы: спаси Мирру` (27) | `Pins & Potions: Tower Rescue` (28) |
| Краткое описание (≤ 80) | `Тяни засовы, смешивай зелья и спаси юную алхимичку!` (51) | `Pull the pins, mix potions and rescue the young alchemist!` (58) |
| Полное описание (≤ 4000) | 1736 символов, ниже | 1828 символов, ниже |

- **Категория:** Игры → Головоломки (Puzzle).
- **Теги** (Play Console → Store settings): головоломка, логическая, казуальная, офлайн.
- **Контакты:** email обязателен (его же увидят игроки); сайт можно не указывать.
- **Язык по умолчанию:** русский (ru-RU); английский (en-US) добавь как перевод.

> Перед первой загрузкой сверь описание с тем, что реально вошло в сборку. Питомцы,
> ингредиенты и «Зелье дня» — функции второго приоритета (DESIGN §16); если какую-то
> вырезали, убери её строку из описания. Писать о том, чего нет в игре, правила Play запрещают.

## 2. Чек-лист релиза (по шагам)

Галочки ставь прямо в этом файле. Шаги идут в том порядке, в котором их удобно делать.

### Шаг 1. Решения, которые не отменить

- [ ] **Название.** По умолчанию «Зелья и засовы / Pins & Potions» (DESIGN §2). Перед этим один раз
  поищи его в Google Play, в базе WIPO (branddb.wipo.int) и Роспатенте.
- [ ] **Package id** — навсегда, после первой загрузки его не сменить. Предложение:
  `com.crownfall90.pinspotions`. Впиши его в оба пресета экспорта (`package/unique_name`).
  Тестовые APK 0.1.0–0.2.0 (`com.alchemytower.game`) тогда станут отдельным приложением — удали их с телефона.
- [ ] **Версия первой загрузки:** `version/name = 1.0.0`, `version/code = 10000` в пресете
  «Android AAB (Play)». **Каждая** следующая загрузка — `version/code` + 1 (10001, 10002…).

### Шаг 2. Ключ загрузки (upload keystore)

Ключом подписывается каждый AAB. Потеряешь ключ — обновления придётся восстанавливать через
поддержку Google, поэтому храни его бережно.

- [ ] Создай ключ один раз (`keytool` лежит в папке `bin` JDK, см. раздел 3):
  ```
  keytool -genkeypair -v -keystore C:\keys\pins-upload.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
  ```
- [ ] Храни `.jks` **вне репозитория** (в `.gitignore` уже есть `*.jks` и `*.keystore`), сделай две резервные
  копии (например, флешка и зашифрованное облако), пароль — в менеджере паролей.
- [ ] При создании приложения в Play Console согласись на **Play App Signing**: Google хранит ключ
  подписи приложения, а твой ключ — только ключ загрузки. Если его потерять, Google может его сбросить.

### Шаг 3. Аккаунт разработчика

- [ ] Зарегистрируйся в Play Console (play.google.com/console), разовый взнос $25.
- [ ] Пройди проверку личности и подтверди, что у тебя есть Android-устройство.
- [ ] Для **нового личного аккаунта** Google требует закрытого тестирования перед продакшеном:
  **не меньше 12 тестеров, которые остаются в тесте 14 дней подряд** (шаг 7). Начинай собирать
  тестеров заранее: друзья, семья, чаты любителей головоломок.

### Шаг 4. Приложение и страница в магазине

- [ ] Play Console → «Создать приложение»: название, язык по умолчанию ru-RU, «Игра», «Бесплатно».
  Подтверди декларации (правила для разработчиков, экспортные законы США).
- [ ] Main store listing: тексты и графика из раздела 1; добавь перевод en-US.
- [ ] Store settings: категория «Головоломки», теги, email.

### Шаг 5. App content (раздел «Контент приложения»)

- [ ] **Политика конфиденциальности:** URL страницы `docs/privacy/index.html` на GitHub Pages (раздел 5),
  например `https://crownfall90-dot.github.io/mobile-game/privacy/`.
- [ ] **Реклама:** «Нет, в приложении нет рекламы».
- [ ] **Доступ к приложению:** «Все функции доступны без особого доступа» (входа нет).
- [ ] **Целевая аудитория:** рекомендуем **13+** (13–15, 16–17, 18+). Если выбрать возраст младше 13,
  игра попадёт под правила Families: строже требования к рекламе и SDK в будущем. Решаешь ты.
- [ ] **Приложение новостей / госорганов / финансов / здоровья:** «Нет».
- [ ] **Advertising ID:** «Нет, приложение не использует рекламный идентификатор».
- [ ] **Data safety** — ответы:
  - «Собирает ли приложение или передаёт ли какие-либо из обязательных типов данных пользователя?» → **Нет**.
  - Остальные вопросы формы после этого не задаются. Итог на странице: «Данные не собираются» и
    «Данные не передаются третьим сторонам».
  - Почему это правда: в игре нет разрешения INTERNET, нет рекламы, аналитики и сторонних SDK.
    Сохранение лежит только на устройстве. Android может положить его в резервную копию аккаунта
    Google игрока (Auto Backup), но разработчик к ней доступа не имеет, поэтому это не считается сбором.
- [ ] **Возрастной рейтинг (анкета IARC)** — категория «Игра», ответы:
  - Насилие: **да, но только мультяшное / фантастическое** — слизни (выдуманные существа) лопаются
    от лавы и кислоты; крови, увечий и реалистичного насилия нет; героиня не гибнет, а пачкается в саже.
  - Страх и ужасы: нет. Сексуальный контент и нагота: нет. Нецензурная лексика: нет.
  - Наркотики, алкоголь, табак: нет (зелья — выдуманные волшебные жидкости, их никто не пьёт).
  - Азартные игры и их имитация: нет (содержимое сундуков фиксировано, реальных денег нет).
  - Общение пользователей, обмен контентом, геолокация: нет. Покупки цифровых товаров: нет.
  - Ожидаемый результат: **PEGI 3 / ESRB Everyone**.

### Шаг 6. Сборка AAB с target SDK 36

- [ ] С 31 августа 2026 года новые приложения и обновления в Play должны нацеливаться на **API 36**.
  В пресете «Android AAB (Play)» уже стоит `gradle_build/target_sdk = 36` и `min_sdk = 24`.
- [ ] Собери AAB по разделу 3 и проверь в Play Console → App bundle explorer: target SDK 36,
  поддержка страниц памяти **16 КБ** — «Да». (В тестовом APK 0.2.0 библиотеки arm64 уже выровнены на 16 КБ.)

### Шаг 7. Закрытое тестирование (12 тестеров × 14 дней)

- [ ] Play Console → Тестирование → **Закрытое тестирование** → создай трек, загрузи AAB.
- [ ] Добавь тестеров: список email или Google-группа. Нужно **≥ 12** человек, лучше 15–20 с запасом.
- [ ] Отправь им ссылку «Присоединиться к тестированию» — каждый должен нажать «Стать тестировщиком»
  и установить игру из Play. Считаются только те, кто **не выходил из теста 14 дней подряд**.
- [ ] Каждые 2–3 дня выкладывай исправления (versionCode + 1) и проси отзывы. Отзывы о прохождении
  тестеры могут прислать кнопкой [Скопировать статистику] в скрытой панели настроек (7 касаний по версии).
- [ ] Прочитай **отчёт о предварительном запуске** (pre-launch report): сбои, скриншоты с разных телефонов.

### Шаг 8. Доступ к продакшену и выпуск

- [ ] Через 14 дней: Play Console → «Панель управления» → **Подать заявку на доступ к рабочей версии**.
  Отвечай честно: сколько было тестеров, что они нашли, что исправлено.
- [ ] После одобрения (обычно до 7 дней): Рабочая версия → новый выпуск → тот же проверенный AAB →
  **поэтапное развёртывание** 20% → 50% → 100%.

### Шаг 9. Каждое обновление

- [ ] `version/code` + 1, `version/name` по смыслу (1.0.1, 1.1.0).
- [ ] Все уровни проходят проверку (`tools/verify.py`), на телефоне проходит самотест (скрытая панель).
- [ ] Если появятся реклама или покупки — сначала обнови Data safety, рейтинг и политику конфиденциальности.

## 3. Как собрать AAB на Windows (Godot 4.5.1)

В контейнере разработки AAB не собрать (нужны Android SDK и загрузки Gradle), поэтому его
собирает владелец. Один раз настроить — дальше сборка в два клика.

### Один раз

1. **Godot 4.5.1**, обычная версия (не .NET), Windows 64-bit: godotengine.org → Download → Archive → 4.5.1.
   Распакуй, например, в `C:\Godot\`. Для консольной сборки есть `Godot_v4.5.1-stable_win64_console.exe`.
2. **Шаблоны экспорта:** в Godot → Editor → Manage Export Templates → Download and Install (4.5.1).
3. **JDK 17** (Godot 4.5 требует именно 17): например, Eclipse Temurin 17 (adoptium.net), установщик `.msi`.
4. **Android SDK:** проще всего поставить Android Studio и открыть SDK Manager (More Actions → SDK Manager).
   На вкладке SDK Platforms: **Android 15 (API 35)** — шаблон Godot компилируется с ним — и **Android 16 (API 36)**.
   На вкладке SDK Tools (включи «Show Package Details»):
   - Android SDK Build-Tools **35.0.0**
   - Android SDK Platform-Tools
   - Android SDK Command-line Tools (latest)
   - NDK (Side by side) **28.1.13356709**
   - CMake **3.10.2.4988404**

   Путь к SDK обычно `%LOCALAPPDATA%\Android\Sdk`.
5. В Godot: Editor → Editor Settings → Export → Android:
   - **Java SDK Path**: папка JDK, например `C:\Program Files\Eclipse Adoptium\jdk-17.0.x-hotspot`;
   - **Android SDK Path**: `C:\Users\<ты>\AppData\Local\Android\Sdk`.
6. Открой проект и выбери Project → **Install Android Build Template…** Появится папка `android/build`
   (она в `.gitignore`, в git её не добавляй). Повторяй этот шаг после каждого обновления Godot.

### Каждая сборка

1. Project → Export → пресет **«Android AAB (Play)»**. Проверь `version/code`, `version/name` и
   `package/unique_name` (шаг 1 чек-листа).
2. Ключ. Вариант А — поля Keystore → Release в том же окне (путь к `.jks`, alias `upload`, пароль).
   Godot хранит их в `.godot/export_credentials.cfg`, который в git не попадает. Вариант Б — переменные
   окружения в PowerShell перед консольной сборкой:
   ```
   $env:GODOT_ANDROID_KEYSTORE_RELEASE_PATH = "C:\keys\pins-upload.jks"
   $env:GODOT_ANDROID_KEYSTORE_RELEASE_USER = "upload"
   $env:GODOT_ANDROID_KEYSTORE_RELEASE_PASSWORD = "<пароль>"
   ```
3. **Export Project** → сними галочку **Export With Debug** → сохрани как `build\pins-and-potions.aab`.
   Или из консоли (в папке проекта):
   ```
   C:\Godot\Godot_v4.5.1-stable_win64_console.exe --headless --path . --export-release "Android AAB (Play)" build\pins-and-potions.aab
   ```
   Первая сборка качает Gradle 8.11.1 и зависимости (нужен интернет, 5–15 минут), следующие быстрее.
4. Загрузи `.aab` в Play Console (сначала в закрытое тестирование).

### Если сборка не идёт

- **«targetSdkVersion 36 больше compileSdkVersion 35» или похожее.** Шаблон Godot 4.5.1 компилируется
  с API 35, а target 36 задаёт пресет. Обычно это только предупреждение. Если Gradle останавливается:
  в `android\build\config.gradle` поменяй `compileSdk: 35` на `36` и добавь строку
  `android.suppressUnsupportedCompileSdk=36` в `android\build\gradle.properties`. В контейнере это
  проверить нельзя — если понадобится, напиши, что именно ответил Gradle.
- **«Java/JDK not found».** Путь в Editor Settings должен вести в корень JDK 17 (где лежит папка `bin`).
- **«SDK location not found» / нет build-tools.** Проверь путь к SDK и что Build-Tools 35.0.0 установлены.
- Лог Gradle при экспорте из редактора показывается в окне сборки, при консольной сборке — в консоли.
  Его и присылай, если что-то сломалось.

### Тестовый APK для телефона

Пресет **«Android»** собирается без Gradle и не требует Android Studio: только шаблоны экспорта,
JDK и минимальный SDK (Platform-Tools и Build-Tools). Файл — `build/pins-and-potions.apk`,
версия 0.2.0 ставится поверх 0.1.0 (тот же package id `com.alchemytower.game`).
Его нельзя загружать в Play: для магазина нужен AAB.

## 4. Что уже сделано в проекте (для сверки)

- Разрешения: только `VIBRATE`, **нет** `INTERNET` (проверено в манифесте тестового APK 0.2.0).
- Auto Backup включён (`allowBackup=true`) — сохранение переживает смену телефона.
- Портретный режим, полноэкранный (immersive), фон окна `#120c24` без белой вспышки при запуске.
- Архитектуры arm64-v8a и armeabi-v7a; у arm64-библиотек выравнивание сегментов 16 КБ.
- Иконки: основная 192 и адаптивные слои 432 (передний план, фон, монохромная для Android 13+).
- Название на иконке берётся из настроек проекта (`application/config/name` и `name_localized`).
- Лицензии Godot показываются в настройках игры (Настройки → Лицензии) — это требование лицензии MIT.

## 5. Политика конфиденциальности на GitHub Pages

Страница уже лежит в репозитории: `docs/privacy/index.html` (RU и EN на одной странице).

1. GitHub → репозиторий → Settings → **Pages**.
2. Source: **Deploy from a branch**, ветка `main`, папка **`/docs`** → Save.
3. Через 1–2 минуты страница откроется по адресу
   `https://crownfall90-dot.github.io/mobile-game/privacy/` (якоря `#ru` и `#en` ведут к нужному языку).
4. Этот адрес — в Play Console (шаг 5) и в строке `store.privacy.url` (`data/strings/store.json`).

GitHub Pages бесплатно работает только для публичных репозиториев. Если репозиторий приватный,
создай отдельный публичный репозиторий только с этой страницей и поменяй адрес в обоих местах.
