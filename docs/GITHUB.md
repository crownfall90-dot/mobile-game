# Разработка Vita на GitHub

- `main` — проверенная версия исходников. Изменения проходят через PR и успешный
  `Vita checks`; защита распространяется и на владельца.
- `claude/project-thread-x4ht8m` — текущая разработка. Обычный push разрешён;
  проверки запускаются автоматически. Force-push и удаление запрещены.
- `apk-builds` — только опубликованные APK и их README. Защищена от удаления
  и force-push. Публичные ссылки из Telegram сохраняются.

## Обычный порядок

1. Получить свежую рабочую ветку, сохранить чужие изменения, выполнить задачу.
2. Отправить законченный этап в рабочую ветку и открыть PR в `main`.
3. Дождаться зелёного `Vita checks`, посмотреть изменения, объединить PR.
   Можно включить Auto-merge: GitHub дождётся обязательных проверок.
4. APK собирать и подписывать прежним ключом отдельно. CI не хранит ключей подписи,
   не выпускает APK и не подтверждает запуск на телефоне.

`Vita checks` проверяет данные уровней, импорт картинок/скриптов, сохранения,
экраны, победу/поражение и правильное решение каждого уровня. Полный G1–G7:
Actions → Vita checks → Run workflow → рабочая ветка → Full level verification.
Обычная проверка не заменяет полный перебор физики и тестирование на устройстве.
Ошибки — через Issues → New issue → «Ошибка в Vita».

Обычные коммиты проекта оформляются от аккаунта владельца `crownfall90-dot`.
Использовать его GitHub noreply email, без подписей автоматических помощников
и без `Co-authored-by` для них. Служебную переписку не добавлять в публичную навигацию.

## Коммит каждого нового APK

С 29.09 отдельная тестовая игра — **Vita Тест**, пакет
`com.crownfall90.vita.test`. Она устанавливается рядом с прежней Vita и начинает
с нового прогресса. Старые APK с `com.crownfall90.vita` сохраняются в `apk-builds`;
удалять старую игру для установки тестовой не требуется.

Постоянный новый ключ — `D:/tools/vita-build/signing/Vita-Test/vita-test.jks`,
алиас `vita-test`, пароль в соседнем `password.txt`; оба файла вне Git, доступ
только владельцу Windows и SYSTEM. Резервная копия —
`C:/Users/crown/Documents/Vita signing backup`. Ключ не менять для следующих
обновлений Vita Тест. Сертификат SHA256:
`0af54d49f655c43ec38bcbb7eb6c63fc0623f39520cdc46afe35ff18a7eb01f0`.

На этом компьютере основная папка и worktree сборки используют ключ через
приватный `.godot/export_credentials.cfg`. Это штатный
[файл секретов экспорта Godot](https://github.com/godotengine/godot-docs/blob/master/tutorials/export/exporting_projects.rst#configuration-files).
Новая копия проекта требует настройки этого файла с тем же ключом; обычный
debug-ключ Godot не обновит опубликованную Vita Тест. Секреты не коммитить.

Публикацию версии в `apk-builds` сопровождает короткий коммит с изменениями
относительно предыдущей опубликованной APK, а не относительно рабочей ветки.
Заголовок: `apk: Vita <версия>`. В теле — только непустые строки «Добавлено: …»,
«Изменено: …», «Убрано: …», по одной короткой строке на категорию.
Указываются только изменения, действительно вошедшие в сборку; внутренние планы
и не опубликованные игрокам персонажи не включаются. При отсутствии удалений
строка «Убрано» пропускается. Несколько архитектур одной версии — один выпуск
с одним описанием. То же краткое описание сохраняется в README сборок/Release.
Историю уже выпущенных APK не переписывать.

## Защита и восстановление

Репозиторий публичный: исходники видны всем, писать может только владелец и
разрешённые им интеграции. Включены защита веток, поиск секретов и блокировка
их push, Dependabot, приватные сообщения об уязвимостях. Actions допускает только
действия GitHub с закреплённым commit SHA; токен CI read-only, без сохранения в git.
Ни токены Telegram/GitHub, ни ключ подписи APK нельзя класть в репозиторий или issue.
Уязвимости: Security → Advisories → Report a vulnerability.

Для аккаунта: включить 2FA/passkey, сохранить recovery codes вне GitHub, проверить
активные сессии и доступы приложений. Эти настройки аккаунта отдельно от репозитория;
их состояние здесь не подтверждено. GitHub Free сохраняет защиту веток в публичном
репозитории; смена на private требует повторной проверки доступных функций и ссылок APK.

Перед большим изменением можно сохранить историю вне проекта:

```text
git fetch origin --prune --tags
git bundle create <внешняя-папка>/vita.bundle --all
git bundle verify <внешняя-папка>/vita.bundle
```

Восстановление: `git clone <путь>/vita.bundle <новая-папка>`. Bundle содержит
закоммиченную историю и ссылки; локальные незакоммиченные/игнорируемые файлы и
ключ подписи в него не входят. Их резервные копии сохраняются отдельно.
Старые ветки доступны через метки `archive/*`, без удаления истории.
