# Продолжение разработки

При старте задачи: `git status --short --branch`, раздел «Текущий статус» в
`docs/ROADMAP.md`, последние 80 строк `docs/HANDOFF.md` и первые 40 строк
`docs/FAMILY_HOME.md`. Дальше читай только разделы по задаче;
если последняя запись обрезана, дочитай её. В том же чате не перечитывай неизменённое.
Актуальная концепция — мама и маленькая дочь, квартира и ремонт через спасательные головоломки.
Старый `docs/DESIGN.md` — архив замысла про Мирру; не возобновляй его незавершённые пункты автоматически.
Продолжай текущую ветку и существующий код. Не начинай заново и не теряй пользовательские изменения.
Проверяй фактическое состояние файлов и git, а не только отметки в документах.
Экономный режим по умолчанию:

- Отвечай кратко по-русски: результат, проверка, существенное ограничение. Без пересказа работы.
- Выполняй только текущую задачу; следующий шаг из журнала не является новым поручением.
- Ищи через `rg` в нужных файлах, читай фрагменты. Не выгружай целиком журналы, большие JSON,
  граф кода, списки инструментов и каталоги навыков. Расширяй поиск, если данных недостаточно.
- Повторно используй существующий код; исправляй общую причину, проверяя всех её вызывающих.
- Без дополнительных агентов, широких аудитов и нового плана для простой задачи.
- Запускай подходящие проверки изменённого поведения один раз после финальной правки;
  повторяй после изменений/ошибок. Не собирай APK без необходимости для задачи.
  Нетривиальная логика должна иметь одну небольшую запускаемую проверку.
- В выводах инструментов оставляй нужные совпадения, итог и ошибки; успех не печатай подробно.
- Context7: только по явному запросу или когда для задачи неясен внешний API,
  а код проекта/локальная документация не дают ответа. Указывай установленную версию
  и конкретный вопрос; начни с одного точечного запроса. Повторно используй найденный
  ID библиотеки и полученные сведения в этом чате; дополнительные запросы только
  для оставшихся вопросов. Не загружай обзор библиотеки и не вызывай при каждой правке.
  Если Context7 недоступен, используй нужный раздел официальной документации.

Память проекта хранится в репозитории; чат — рабочая сессия, не единственное хранилище.
- `docs/ARCHITECTURE.md`: действующие модули/потоки и раздел «Решения»
  (дата, принято/предложено/заменено, решение, причина, существенное ограничение).
- `docs/ROADMAP.md`, «Текущий статус»: готово, в работе, блокеры, проверка, следующий шаг.
- ChatGPT планирует по `docs/CHATGPT.md`; конкретный этап — «Задание Codex» в ROADMAP.
  На «Выполни задание <ID>» прочитай его, сверь с кодом/git и выполни без
  повторного объяснения проекта. Зафиксируй результат/блокер и обнови статус;
  не запускай новую задачу только из-за её наличия в плане.
Маркеры промпта: `/codex` — исполняемое задание, `/brief` — кратко,
`/no-invent` — проверенные факты, явно отмечать неизвестное; это наши условные метки.
- `docs/HANDOFF.md`: краткая история этапов с проверками и ограничениями.
Перед завершением сессии сохрани новые требования/решения и незавершённую работу
в нужных разделах, обнови текущий статус. Архитектуру меняй только при изменении
структуры/потоков; историю не переписывай. Не дублируй детали, ставь ссылки.
Новая сессия должна продолжаться по этим файлам без чтения старого чата;
предложение не отмечай принятым без основания, непроверенное не называй готовым.
Перед остановкой сохраняй проверенную работу коммитом и отправляй текущую ветку на GitHub, если доступен push.
Не заявляй о проверке Android на телефоне без реального запуска на устройстве.

При фактическом выпуске новой Vita Тест после публикации и проверки GitHub Release
сразу отправляй владельцу в личный чат через существующего `vita_reliz_bot`:
прямую ссылку на основной arm64 APK и сам APK как Telegram document. Используй
только локальные секреты/состояние вне Git, проверяй ответ Telegram и защищайся
от дублей по версии и SHA256. Если Bot API отклонил файл из-за размера, ссылку
всё равно отправь, файл не помечай доставленным и кратко сообщи владельцу точную
причину. Это правило выполняется внутри задачи релиза; фоновый монитор не включать.

Перед каждой сборкой/публикацией Vita Тест синхронизируй и проверь одним
запускаемым check: `application/config/version` в `project.godot`, `version/name`
и `version/code` в обоих Android-пресетах. Settings и Reports читают именно
версию проекта, поэтому совпадения одного Android manifest недостаточно. После
сборки для каждой ABI проверь package `com.crownfall90.vita.test`, versionName,
versionCode, единственную нужную ABI, подписи v2/v3 и прежний сертификат. GitHub
asset заменяй только после этих проверок и сверки SHA256; затем обновляй локальную
защиту Telegram от дублей. Не объявляй релиз готовым, если версия в Settings
отличается от APK.
